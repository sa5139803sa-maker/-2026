# إدارة الحسابات وكلمات المرور — Water Management

## الأدوار
- `platform_admin`: دور منصة مستقل لا ينتمي إلى مؤسسة، ومخصص للوحة إدارة المنصة على الويب فقط. لا يُسمح له بتسجيل الدخول إلى تطبيق Expo (Android أو تصدير Expo للويب)، ولا توجد له قوائم أو شاشات أو عمليات داخل تطبيق العاملين. ينشئ حسابات مديري المؤسسات أو موظفي مؤسسة محددة ويضبط حد الحسابات من الويب.
- `manager`: يستخدم تطبيق Expo الميداني ولوحة إدارة مؤسسته على الويب، وينشئ operator وcollector وsupervisor داخل مؤسسته ويعيد تعيين كلمات مرور موظفي مؤسسته فقط.
- مدير المؤسسة لا يدير حسابات مؤسسة أخرى أو حساب مدير المنصة.

## حدود الحسابات
- `organizations.account_limit` افتراضيًا 5، والعدد يشمل مدير المؤسسة وكل الموظفين.
- لا يسمح بإنشاء حساب عند بلوغ الحد، ولا بخفض الحد عن العدد الحالي.
- الإنشاء وتعديل الحد يقفلان صف المؤسسة لمنع تجاوز الحصة عند التزامن.

## كلمة المرور المؤقتة
- ينشئ الخادم حساب Auth باسم مستخدم وكلمة مرور عشوائية مؤقتة.
- يعرض التطبيق اسم المستخدم وكلمة المرور مرة واحدة بعد النجاح؛ تُسلّم عبر قناة آمنة ولا تحفظ في قاعدة البيانات أو سجل التدقيق.
- عند أول دخول يُمنع المستخدم من بيانات المؤسسة حتى يختار كلمة مرور جديدة.
- كلمة المرور الجديدة: 10 أحرف على الأقل، حرف كبير، حرف صغير، ورقم.
- إعادة التعيين تصدر كلمة مؤقتة جديدة وتعيد فرض التغيير.
- `session_invalid_before` يمنع رموز JWT الأقدم من إعادة التعيين من الوصول إلى بيانات المؤسسة حتى بعد تغيير كلمة المرور. قد يظل access token القديم صالحًا لدى Auth حتى انتهاء صلاحيته؛ لا يعني ذلك حذفه تشفيريًا.

## اسم المستخدم
- يتحول اسم المستخدم داخليًا إلى بريد اصطناعي ضمن `login.water-management.invalid` للتوافق مع Supabase Auth؛ لا تُرسل رسائل إلى هذا النطاق.
- تسجيل الدخول يقبل اسم المستخدم للحسابات الإدارية والبريد للحسابات القديمة.
- يسمح بالحروف العربية أو اللاتينية والأرقام والنقطة والشرطة والشرطة السفلية؛ الطول 3–40.

## الخادم والتدقيق
- العمليات الإدارية تمر عبر Edge Function `manage-accounts` مع `verify_jwt=true`.
- مفتاح service role يبقى في بيئة Supabase الخادمية ولا يدخل Expo أو Git.
- `account_audit_log` يسجل إنشاء الحساب وإعادة التعيين وتغيير كلمة المرور وتعديل الحد دون حفظ كلمة المرور.
- سجل التدقيق غير قابل للقراءة من anon/authenticated.

## تهيئة أول مدير منصة
1. أنشئ حسابًا موثوقًا من Supabase Dashboard > Authentication > Users.
2. انسخ UUID الخاص بالمستخدم.
3. نفّذ في SQL Editor لمشروع التطوير بعد استبدال UUID واسم المستخدم:
```sql
UPDATE public.profiles
SET role = 'platform_admin'::public.app_role,
    organization_id = NULL,
    username = 'platformadmin',
    must_change_password = false,
    session_invalid_before = NULL
WHERE id = 'REPLACE-WITH-TRUSTED-AUTH-USER-UUID';
```
4. تحقق أن صفًا واحدًا فقط عُدّل، ثم سجّل الدخول. لا تنفذ هذا الإجراء لمستخدم غير موثوق.

## فصل التطبيق عن الويب
- تطبيق Expo للعاملين الميدانيين وأدوار المؤسسة فقط. يرفض تسجيل دخول `platform_admin` ويغلق أي جلسة قديمة لهذا الدور.
- لوحة إدارة المنصة ولوحة المؤسسة وبوابة المشترك واجهات ويب ضمن تطبيق Next.js مستقل. تطبيق Next.js لم يُنشأ بعد؛ لا تعتبر شاشة Expo أو تصديرها للويب بديلًا عنه.

## الحالة
ترحيلات قاعدة التطوير مطبقة وEdge Function منشورة، وأول حساب `platform_admin` مهيأ في قاعدة التطوير. حواجز Expo اجتازت Quality CI #128، واختبارات العزل اجتازت PostgreSQL CI #156. يلزم اختبار دورة حسابات المؤسسة على Android وبناء تطبيق Next.js واختباره قبل اعتماد المنتج للإنتاج.

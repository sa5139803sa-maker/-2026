# تطبيق الويب — إدارة المياه

تطبيق مستقل باستخدام Next.js App Router، وليس نسخة ويب من تطبيق Expo.

## المسارات

| المسار | الاستخدام | الوصول |
|---|---|---|
| `/login` | تسجيل دخول الإدارة | عام |
| `/platform` | لوحة إدارة المنصة وإنشاء المؤسسات وإدارة حساباتها | `platform_admin` فقط |
| `/organization` | لوحة مدير المؤسسة وإدارة حسابات موظفي مؤسسته | `manager` فقط |
| `/change-password` | تدوير كلمة المرور المؤقتة | مدير منصة/مؤسسة يفرض عليه التغيير |
| `/portal` | بوابة المشترك | عام، يتطلب رقمًا عالميًا من 6 خانات ورقم الهاتف المسجل فقط |

العاملون الميدانيون (`operator`, `collector`, `supervisor`) يستخدمون تطبيق Android. لا يمنحهم هذا التطبيق دخولًا إلى لوحة الويب. ودور `platform_admin` مخصص للويب، كما يرفض تطبيق Expo تسجيل دخوله.

## التشغيل المحلي

المتطلبات: Node.js 22.12 أو أحدث وnpm.

```powershell
cd apps/web
Copy-Item .env.example .env.local
```

أدخل رابط مشروع Supabase ومفتاحه العام (Publishable Key) في `.env.local`:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

يمكن استعمال مفتاح `anon` القديم كحل توافق مؤقت عبر `NEXT_PUBLIC_SUPABASE_ANON_KEY`. لا تضف `service_role` أو أي Secret Key إلى متغير يبدأ بـ `NEXT_PUBLIC_` أو إلى مستودع Git.

```powershell
npm install
npm run dev
```

ثم افتح `http://localhost:3000`.

## المصادقة وحدود الثقة

- `@supabase/ssr` يستخدم Cookies وPKCE للويب.
- `proxy.ts` يحدّث الجلسة فقط؛ ليس حاجز التفويض النهائي.
- كل صفحة محمية تتحقق على الخادم باستخدام `auth.getUser()` ثم تجلب ملف الصلاحيات من `profiles` وفق RLS.
- لا يعتمد التفويض على user metadata أو دور مخزن في المتصفح.
- عمليات إدارة الحسابات تمر عبر `POST /api/admin/accounts`: تتحقق من Origin والجلسة والملف الشخصي والدور، ثم تمرر JWT المستخدم إلى Edge Function `manage-accounts`.
- إنشاء المؤسسة ينفذه RPC من نوع `SECURITY INVOKER` لا يملك صلاحية تنفيذه إلا `service_role`؛ تنشأ المؤسسة وسجل التدقيق ضمن معاملة واحدة.
- لا يستخدم تطبيق الويب `service_role` مطلقًا ولا يضعه في العميل.

## فحوص الجودة

```powershell
npm test
npm run typecheck
npm run build
```

إصدارات الاعتماديات المباشرة مثبتة بأرقام دقيقة في `package.json`. في CI وVercel يُولّد `package-lock.json` من هذه الإصدارات عبر `npm install --package-lock-only` ثم تُثبت الشجرة بواسطة `npm ci`. يحتفظ CI بملف القفل كأثر تدقيق لمدة 7 أيام؛ ملف القفل غير متتبع حاليًا في Git، لذلك لا ندّعي أنه committed.

## حدود النسخة الحالية

- إدارة المؤسسات والحسابات والحصص وكلمات المرور المؤقتة هي الوظائف التشغيلية الأساسية في هذه الدفعة.
- لا توجد بعد إدارة حالة تفعيل/تعليق المؤسسة أو سجل تدقيق تفاعلي شامل داخل لوحة المنصة.
- بوابة المشترك تستدعي Edge Function عامة واحدة باسم `subscriber-portal` مباشرة من المتصفح بالمفتاح العام فقط؛ الدالة تحصل على IP من بوابة Supabase وتستدعي RPC داخلية محصورة في service_role. المطابقة برقم اشتراك عشوائي عالمي من 6 خانات والهاتف المسجل فقط، دون OTP أو رسائل نصية. لا تُكشف بيانات عند عدم التطابق، ولا يمكن للعميل قراءة جدول subscribers مباشرة. يعرض الإصدار الحالي البيانات الأساسية فقط؛ لا توجد بعد سجلات مالية أو تعبئات مرتبطة بالبوابة.
- هذا المستودع يستهدف مشروع Supabase `kxdncnswbwktbiphptbr` مباشرة، وهو المشروع الأساسي المعتمد ليصبح الإنتاج لاحقًا؛ لا توجد خطة لنقل قاعدة البيانات إلى مشروع Supabase آخر. ترحيلة بوابة المشترك مطبقة عليه، وEdge Function `subscriber-portal` نشطة بالإصدار 2 مع `verify_jwt=false`. اختُبر التطابق الصحيح ورفض الهاتف الخاطئ وقبول الأرقام العربية ببيانات مؤقتة انتهت بـ`ROLLBACK`.
- الهاتف ليس فريدًا داخل المؤسسة؛ يمكن لأفراد الأسرة مشاركة الهاتف نفسه. رقم الاشتراك وحده فريد عالميًا.
- لا تعتبر هذه النسخة جاهزة لفتحها للعامة قبل اختبار HTTP end-to-end وواجهة المتصفح على نفس المشروع ببيانات اختبار مؤقتة تُزال بـ`ROLLBACK`، والتحقق من IP headers ومحددات المحاولات، وضبط الاستضافة والنطاقات وHTTPS، وتفعيل leaked-password protection، ومراجعة النسخ الاحتياطية واختبار الأدوار.

### بوابة المشترك — آلية الوصول

- الرقم عشوائي من 6 خانات (100000–999999)، وفريد على مستوى المنصة كلها، وليس داخل المؤسسة فقط. ينشأ في قاعدة البيانات، ولا يُعاد استخدام الرقم بعد حذف الاشتراك.
- الاستعلام يتطلب الرقم والهاتف المسجل معًا؛ لا توجد خطوة OTP ولا خدمة إرسال SMS.
- الهاتف يوحّد إلى صيغة رقمية معيارية في قاعدة البيانات، مع قبول الأرقام العربية والفارسية والصيغ الفلسطينية والدولية.
- حدود المحاولات الحالية: 10 لكل IP خلال 15 دقيقة، و5 لكل رقم اشتراك خلال ساعة، و5 لكل هاتف معياري خلال ساعة. تُخزّن مفاتيح الحدود بصيغة HMAC لا كقيم الهاتف أو IP خام.
- يستدعي المتصفح عنوان Supabase Edge Function مباشرة؛ لا يمر استعلام المشترك عبر Vercel. تقبل الدالة فقط `cf-connecting-ip` الذي تضيفه بوابة Cloudflare المُدارة من Supabase، وتتجاهل `x-forwarded-for` و`x-real-ip` و`x-vercel-forwarded-for` وأي IP في جسم الطلب. عند غياب الرأس أو تشوهه تفشل مغلقة بـ503. لا تضع الدالة خلف Proxy لا يزيل الرؤوس المرسلة من العميل ويثبت مصدر عنوان العميل.
- لا يعرض البحث إلا الاسم ورقم الاشتراك والغطاس ورمز الغطاس وآخر أربعة أرقام من الهاتف. تفاصيل التعبئات والمستحقات تحتاج جداول وخدمات مالية وتشغيلية لم تُبنَ في قاعدة البيانات حتى الآن.
